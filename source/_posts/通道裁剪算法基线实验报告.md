我们要搞清楚的几件事：

1.我们假设当前DL系统存在大量的隐藏层冗余，且删除这些冗余不会对准确度有很大影响。

2.系统存在一个“最小可拟合维度”这一点在以前的工作已经证明，但是我们无法在未知分布的系统上估计出最小可拟合系统到底是多少，我们尝试采用裁剪算法来毕竟一个下届

本文记录了有关三个任务怎么定义、参数怎么确定、跑了什么、基线结果是什么、结论和边界各是什么。

---

## 摘要

我们造了三个**难度接近、但类型完全不同**的小任务（MQAR、BoundedDyck、随机双分布），用同一套“阈值冻结两阶段裁剪”把 4 层 Transformer / Mamba 的每层通道压窄。以 λ=0.7 当基线：（i）MQAR 能压到约 5–10 个通道，准确率不掉；（ii）BoundedDyck 的 Mamba 收敛了，但 Transformer 没收敛（hidden 越大压得越宽）；（iii）随机双分布完全没收敛。也就是说，同样一个压缩力度下，越“难”的任务越压不动，而这里的“难”跟任务的熵率 $H(Y\mid X)$ 是同一个方向。

## 1. 我们想干什么，以及这里说的“裁剪”是什么

1. 同一个任务，你把起始 hidden 从 48 换到 96，模型最终表现几乎不变，但它实际用到的有效通道数会变多。我们想知道：**裁剪能不能把这些多出来的通道压掉，压到一个跟起始 hidden 无关的宽度？**
2. 如果三个结构完全不同的任务都能在差不多的紧凑宽度上停下来，那这个宽度就有点像“这个任务的最低实现宽度”；压不下来，就说明它其实还和算法、和压缩力度 λ 有关，不只是任务本身决定。
3. 为了让“宽度”能横向比，得先把三个任务的预测难度弄得差不多，我定义了难度评估的方法——这也是后面参数、token、长度都这么选的原因（见第 3 节）。

**这里说的“裁剪”（两阶段，全文都按这个口径）**

- 每层有一个可以学的“宽度” $k_l$，门的开合是 $g_j=\sigma(k_l-j+0.5)$；门管的是这一层输出 hidden 的最后一维。
- **阈值冻结**：$g_j<0.5$ 的通道，前向直接置零、反向断开梯度，而且**一旦关掉就再也回不来**；被关掉的永远是**连续的一段前缀**。
- **两阶段**：阶段一先把门旁路掉，正常训练到早停，把最好的全量模型存下来；阶段二从这份全量最优复制一份，把门打开，让 $\lambda$ 从 0 慢慢升到目标值，通道随着训练被一个个关掉，直到早停。
- **怎么选最好的模型**：第二阶段里挑 $\text{验证CE}+\lambda_{\text{target}}\times\text{有效宽度比}$ 最小的那个（越窄越准越好）。**这里不用 KL 选。**
- **宽度怎么数**：$\text{有效宽度比}=\text{有效宽度}/\text{最大宽度}$；$\text{绝对宽度}=\text{有效宽度比}\times\text{hidden}$。

## 2. 三个任务长什么样（怎么造的 + 例子）

三个任务走的是同一套训练/裁剪/评估流程，只有生成数据的部分不一样。它们分别代表三类不同的“记忆”：**记住谁等于谁**、**记住栈里还剩啥**、**看不见状态只能靠概率猜**。

### 2.1 MQAR：先告诉你几个“键=值”，最后考你某个键对应啥

一条样本是这么造出来的：

1. 词表分三块：0–5 当键，6–11 当值，再留一个“提问符” `Q`(12)、开头符 `BOS`(13)、占位符 `PAD`(14)，一共 15 个。
2. 每条序列自己随机挑 3 个不一样的键。
3. 一对一对地写进去：先发一个键，再随便给它配个值，记下“这个键等于这个值”。注意**顺序、值、后面要考哪个键都是随机的**，所以模型看到的是“接下来可能是这几个键/这几个值”的概率，而不是一条死板的固定串。
4. 写完开始考，一共考 4 次。每次先发个 `Q`，再随机挑一个刚写过的键发出去，然后——就是要模型猜的——该放它对应的值。
5. 一条正好 18 个 token（3 对写入各 2 个 + 4 次问答各 3 个）。

从数据里随便挑一条（下面这个是**数据里记录的正确答案**，不是模型的输出）：

```text
K3 v1   K5 v1   K4 v3   |  Q K5 -> v1 | Q K3 -> v1 | Q K3 -> v1 | Q K5 -> v1
```

翻译一下：先写了“K3=v1、K5=v1、K4=v3”三对，然后连着问 K5、K3、K3、K5，**这四条正确答案都是 v1**。。

### 2.2 BoundedDyck：一串括号，看它记不记得栈里还剩啥

一条样本是这么造出来的：

1. 词表：0–7 是 8 种左括号，8–15 是 8 种右括号，再加 `BOS`、`PAD`，一共 18 个。
2. 心里维护一个栈（就是“还没配对上的左括号”按顺序摞着）。
3. 每一步按当前栈决定“下一步能发啥”：
   - 栈空了 → 只能发左括号，8 种里随便挑；
   - 栈不空 → 有两种可能性
     - 要是栈已经满到 10 层，或者剩下的长度不够再收尾了 → 没得选，必须闭；
     - 否则有 **68%** 的概率新开一个括号（8 种里随便挑），**32%** 的概率把栈顶闭掉。
4. 按这个概率抽一个发出去；发的是左括号就压栈，是右括号就弹栈。
5. 一条固定 64 个 token；“快没地方了就强制闭合”的规则保证发完时栈一定是空的（所以是合法的括号串）。

例子（真跑出来的，`<3` 表示“左3”，`>3` 表示“右3”）：

```text
<3 <5 <0 >0 <0 <4 >4 <6 >6 >0 <3 >3 >5 >3 <7 >7 <5 >5 <0 <5 <5 <2 <0 <5 >5 >0 ...
```

念法：先开了 3、5、0（栈里是 `[3, 5, 0]`），接着 `>0` 就是把最上面的 0 闭掉，后面照此循环；只要栈是空的（比如开头），下一步必定是个左括号。

### 2.3 随机双分布：状态藏起来，还经常一步分叉到好几个状态

一条样本是这么造出来的：

1. 一共 20 个不同的隐藏状态（下一步采样分布）；普通 token 16 个，再加一个结束符 `EOS`。
2. **转移是随机的**：对每一种“（当前状态, 发出去的 token）”组合，随机挑 5 个不同的“下一步可能去哪个状态”，再给这 5 个配一组概率。所以同样的（状态, token），下一步可能落到好几种状态上。
3. 每个状态还有自己的一整套“下一步发哪个 token”的概率（16 个普通 token + EOS 全都有正概率）。这套概率是把一个随机矩阵做了“限秩”（只留 10 个方向）再归一化得到的。
4. 生成时从头开始：先按当前状态的概率采一个 token 发出去，再按（状态, token）那组 5 选 1 的概率采下一个状态……一直发到 `EOS`；最长 56 个 token（平均约 26.5 个）。
5. **最关键的一点**：模型**看不到真实状态**。要它预测的是“看完已经发出的 token 之后，对下一个 token 的合理猜测”（把这些可能的状态按概率加权）。所以下一个 token 天生带“好几个状态可能同时成立”的模糊性。

名字里的“双分布”，说的是每一步都有两层概率：**“状态→token”的发射概率**，和（状态,token）→下一状态”的转移概率，模型得把这两层揉在一起才能猜准。

看个真例子（真实状态只有我们看得到）：

| 位置 | 真实状态 | 发出的 token | 模糊度(bit) | 这一刻“下一步 token”的前 5 名                  | 这一刻的 5 个候选下一状态                              |
| ----:| --------:| ------------:| -----------:| ---------------------------------------------- | ------------------------------------------------------ |
| 0    | 0        | 2            | 0.00        | 2:0.731, 8:0.106, 3:0.041, 10:0.040, 9:0.020   | 14:0.06, 5:很小, 8:0.67, 17:很小, 15:0.26 → 实际去了 8 |
| 1    | 8        | 7            | 1.15        | 7:0.166, 11:0.162, 5:0.136, 13:0.085, 15:0.076 | 13:0.45, 5:0.03, 9:0.12, 18:0.40, 0:≈0 → 实际去了 18   |
| 2    | 18       | 12           | 1.59        | 3:0.332, 6:0.263, 12:0.099, 5:0.097, 4:0.068   | （继续……）                                             |

简而言之就是一个马尔可夫过程，想象一个agent，它前往下一步有20选5种可能性，候选名单根据当前token来确定，每个token的下一条候选的分布是不一样的，进入下一步后，这一步会采样得到当前步的token，每种可能性会采样到的token的分布是不同的。

三个任务的数据量、batch、学习率、早停、后处理和 hidden 档位**全都一样**，唯一变的就是任务本身。而且三档只改 hidden，还固定用**同一个任务实例**（`fixed_task_instance=true`），免得任务实例换个随机种子就把跨档比较搞乱了。

## 3. 参数怎么定的，为什么这么定

### 3.1 序列长度

| 任务        | 长度 | 为什么这么长                                                                              |
| ----------- | ----:| ----------------------------------------------------------------------------------------- |
| MQAR        | 18   | 只够放下“3 对写入 + 4 次问答”就行，本来就是短程绑定；拉长只会塞进一堆没关系的远距离噪声。 |
| BoundedDyck | 64   | 栈深能到 10，得让它真能摞起来，“没闭合的栈”才算得上是长程状态。                           |
| 随机双分布  | 56   | 让信念在好多步转移之后有机会发散、再收敛，保留长程滤波的需求。                            |

目的：让三个任务的“依赖长度”天然不一样（短程绑定 / 长程计数 / 长程滤波），同时又不让谁因为太短而退化成近似马尔可夫任务。

### 3.2 token（词表）

- 各任务词表基本就是它结构需要的最小值：MQAR 15、BoundedDyck 18、随机双分布 16。
- 主实验故意**不强求统一词表**，是为了保留每个任务本来该有的预测分布形状；词表差异到底有没有影响，留待后续重新设计的消融来查。
- 这些词表都比正式大任务小得多（正式 MQAR 词表能到 97），因为正式实验训练时长太久了所以我们采用小样本来做第一步验证。

### 3.3 数据量

- 三个任务 × 三个档位，统一用 `train/validation/test = 8192 / 2048 / 2048`。
- 数据量选 8192 这个低样本规模；它到底是不是瓶颈，留待后续重新设计的消融来查。

### 3.4 起始 hidden 为什么是 48 / 64 / 96

原来想过 h32/h64/h128，放弃了：

1. h32 已经快贴到能压的最小宽度了，没什么可压的余量，压不出信号；
2. h128 相对这些小任务跳太大，会把“hidden 变大”和“任务/数据变化”搅在一起，说不清。

### 3.7 三个任务的复杂度是否在同一水平（用两个指标量一下）

在生成器上直接算（单位 bit）：

| 任务        | $H(Y\mid X)$ (bit) | $r_{\text{Bayes}}$ | 词表 $V$ | 均匀熵上界 $\log_2 V$ |
| ----------- | ------------------:| ------------------:| --------:| ---------------------:|
| MQAR        | 0.927              | 8.83               | 15       | 3.91                  |
| BoundedDyck | 2.124              | 7.90               | 18       | 4.17                  |
| 随机双分布  | 3.062              | 8.88               | 17       | 4.09                  |

- $r_{\text{Bayes}}$（预测到底需要几个独立方向）：三个任务 7.90–8.88，最大和最小只差 1.12 倍（≤3）→ **在同一量级**。
- $H(Y\mid X)$（还剩多少搬不动的不确定）：0.93 到 3.06，差了 3.3 倍（略微超过 3 倍）→ 三个任务的“不可约噪声”并不相等，MQAR 最确定，随机双分布最模糊。
- 所以我们按主指标 $r_{\text{Bayes}}$ 认定它们难度对齐、可以放在一起比宽度；但 $H$ 的这个差别要一直记着（见结论第 4 条）。

**一眼看收敛（λ=0.7）**

| 任务        | TF h48/h64/h96        | Mamba h48/h64/h96     | h96/h48（TF / Mamba） | 收敛了吗                     |
| ----------- | --------------------- | ---------------------:| ---------------------:| ---------------------------- |
| MQAR        | 9.95 / 7.94 / 5.49    | 6.15 / 4.90 / 7.22    | 0.55 / 1.17           | **收敛**（约 5–10）          |
| BoundedDyck | 11.97 / 14.71 / 18.35 | 10.15 / 7.43 / 6.36   | 1.53 / 0.63           | 一半（TF 随 hidden 变大）    |
| 随机双分布  | 9.95 / 14.81 / 28.80  | 20.48 / 27.00 / 50.86 | 2.89 / 2.48           | **没收敛**（随 hidden 变大） |

**从基线里能直接看到的**

- 全量模型 h48/64/96 表现几乎一样（MQAR≈0.58、BD≈0.50、随机双分布≈0.31）——**大 hidden 并不提升性能，只是多用通道**。
- 裁剪在 MQAR 上几乎不掉点（最多掉 0.2pp）；BoundedDyck 掉 0–2pp；随机双分布掉 0.4–0.6pp，而且 KL 明显变高。
- 只有 MQAR 在 λ=0.7 就收敛了，另外两个任务在同一个 λ 下压不下来。

---

## 5. 结论

1. **裁剪确实能收敛出“最低实现宽度”，但不是所有任务都行**：MQAR 在 λ=0.7 就收敛（约 5–10 个通道，跟起始 hidden 无关）；BoundedDyck 的 Mamba 收敛、Transformer 不收敛；随机双分布在 λ=0.7 完全没收敛。
2. **越难的任务，在同一个 λ 下越压不动**：MQAR（H=0.93）在 λ=0.7 就收敛；BoundedDyck（2.12）勉强；随机双分布（3.06）在 λ=0.7 下完全压不动。**“压不压得动”和 $H(Y\mid X)$ 是同方向的。**
3. **难度对齐了，宽度却没完全对齐**：三个任务 $r_{\text{Bayes}}$ 已经对齐（7.90–8.88），但 λ=0.7 下同一任务内的宽度还是随 hidden 变（随机双分布 h96/h48≈2.5–2.9）。说明“绝对宽度”不只由 $r_{\text{Bayes}}$ 决定，还受 λ 和架构影响；想把三个任务压到同一个数，可能得各自用各自的 λ。
4. **大 hidden 不提升性能、只多用通道**；裁剪把多余的压掉，代价是 KL 变大，Top-1 准确率在容易的任务上基本不掉。
5. **架构差别很大**：随机双分布上 Mamba 比 Transformer 更难压。
6. **裁剪对 hidden 信息率和决策头使用率的影响**：MQAR 裁剪后 hidden 信息率几乎不变（≈0.90），说明压到 5–10 个通道仍保留了几乎全部可读状态信息；BoundedDyck 裁剪后信息率明显下滑（Mamba 尤甚，h64 从 0.983 掉到 0.700），说明压过头会丢掉可读状态信息；随机双分布只小幅下降（≈0.87 → 0.82–0.86）。决策头使用率（有限 probe 相对使用率）多数在 0.9 以上，说明原预测头基本已经用上了参考 probe 能读到的预测信息、读取瓶颈不突出；个别例外（BoundedDyck h64 Mamba = −0.112）属“参考 probe 未证明更强、不可判定”。

**一句话**：$r_{\text{Bayes}}$ 是个不错的“这任务需要几个预测方向”的主坐标；但“最低实现宽度”是个**跟算法和 λ 有关的经验量**，想把不同任务压到同一宽度，得按难度分别挑 λ。

---

## 6. 边界与限制

1. **经验值不等于理论下界**：报告里的宽度是当前算法在给定 λ/数据下能压到的**软有效前缀宽度**，不是严格的代数最小充分维度，也不是部署时真的用到的物理宽度。
2. **任务规模比正式任务小**：词表和长度都比正式大任务小（比如 MQAR 词表 15 vs 97），**还没证明跟正式 36 模型的景观等价**；结论只在“低维投影”这套口径里成立。
3. **没做物理裁剪**：现在模型还是“冻结掩码模型”，没真的裁成一个更小的模型，所以没报真实参数量 / FLOPs / 延迟，也没验硬门和物理模型之间的最大预测差。
4. **单种子、单任务实例**：每个任务只用了一个任务实例（`fixed_task_instance`）和一个模型种子，还没给跨实例/跨种子的置信区间。
5. **三个任务并不是完全同一个难度**：$H(Y\mid X)$ 差了 3.3 倍，横向比宽度时得把“不可约噪声不同”算进去。
6. **只有一个统一基线 λ=0.7**：还没给出每个任务各自的收敛 λ，也没查清不同任务“压过头 / 没压够”的边界。
